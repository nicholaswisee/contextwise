# Contextwise v0.0.0 — Engineering Foundation

## User-visible changes

- New `/health/live` endpoint: returns `{"status": "alive"}` and never depends on external services.
- New `/health/ready` endpoint: returns `{"status": "ready"}` when PostgreSQL is reachable and migrations are applied; returns HTTP 503 otherwise.
- All HTTP responses include an `x-request-id` header for request correlation.
- JSON-structured application logs are emitted to stdout.

## Architectural changes

- uv is the package manager (ADR-0001).
- FastAPI application factory `create_app()` with async lifespan management.
- Layered package structure: `api`, `application`, `infrastructure`.
- Pydantic Settings load from environment and `.env`.
- Async SQLAlchemy engine/session with `Database` adapter.
- Alembic migrations under `src/contextwise/infrastructure/migrations`.
- Docker Compose for API + PostgreSQL.
- GitHub Actions CI for lint, format, type, unit tests, and migrations.

## Known limitations

- The initial migration is a placeholder with no schema objects yet.
- Readiness does not yet verify the migration revision equals `alembic heads`.
- No persistent domain models or business logic beyond health checks.

## Deferred work

- Add domain models and their migrations in Milestone 1+.
- Add tracing and metrics beyond request IDs and JSON logs.
- Add graceful-shutdown test for an in-flight request.
